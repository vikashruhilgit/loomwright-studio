## Task
**Goal:** Make every Result chip in Schedules' firing history show its whole text inside the table, at the window's default size and at its minimum size, in light and dark. The raw reason line (`playbook_not_enabled`) stays beneath it.

**Problem Statement:**
In the 2026-11-01 live re-run (`schedules-populated`, light and dark, default window size), the firing history's Result chip "playbook off: fires are skipped" was cut to "…fires are skippe" on every row, with no wrap and no ellipsis. On the owner's store these rows make up most of the history.

**Root cause (grounded at base):**
1. **Default size (1180 × 760, `app/electron/main.ts`: `width: 1180, height: 760`).** The Result column is fixed at `.schedules-c3 { width: 176px; }`, and every cell clips (`.schedules-fire td { … overflow: hidden; … }`). The chip is a `Badge` (`app/src/components/Badge/Badge.css`: `.badge { … height: 20px; … white-space: nowrap; }`, caption type at `--type-caption-size: 11px`, weight 600). Its 31-character label is about 200px wide plus padding, which is wider than the 160px left inside the cell's `var(--space-2)` padding. The text can't wrap, so the cell's `overflow: hidden` cuts it. The column is the table's rightmost, so the cut sits at the pane's right edge, which is what the owner saw. When a group folds repeats, the `×N` count sits in the same flex row (`.schedules-result { display: flex; … }`), which leaves even less room.
2. **Minimum size (`minWidth: 900, minHeight: 560`).** The pane is 900 − `--sidebar-width: 240px` − `--list-pane-width: 360px` = 300px wide. `.schedules-pad`'s `padding: var(--space-5) var(--space-6)` leaves about 252px for the table. The two fixed columns already add up to 96 + 176 = 272px, so the fixed-layout table is wider than its pane. The pane (`.schedules-pane { … overflow: auto; }`) then scrolls sideways, and the Result column ends past the window edge before any chip text is considered.

**Owner decisions (Launch Pad, 2026-11-01, binding):**
1. **Touches extended (`LP-TOUCHES`).** Add `docs/evidence/phase-7-polish/schedules/**` (the README and the regenerated PNGs) so the polish-gate evidence is committed. The PR body links to the README.

**Design decisions this brief makes (conventional defaults; the PR names each for the owner):**
- **The chip wraps in its cell, and no ellipsis is used.** A scoped override in `schedules.css` lets a Badge inside `.schedules-result` wrap: `white-space: normal`, `height: auto` with a 20px minimum, and `max-width: 100%`. `.schedules-result` gets `flex-wrap: wrap; min-width: 0`, so `×N` drops under the chip when there's no room. The shared `Badge.css` is not edited. The requirement asks for the whole text, so an ellipsis would not meet it.
- **The table fits its pane at the minimum size.** The fixed column widths no longer exceed the pane. Shrink `.schedules-c1` and `.schedules-c3` (for example with a `@container` query on the pane, or with widths that sum below 252px), so the Trigger column keeps a usable width and the chip, now able to wrap, fits. The worker picks the exact widths by measuring at 900 × 560. The constraint is the AC2 assertion, not a number.
- **Row height.** `.schedules-fire { height: 64px; }` stays as the minimum (a table row's `height` is a minimum). A row whose chip wraps grows to fit, and every cell keeps `vertical-align: top`, so the three columns stay aligned. A row's height depends only on its own content. A refetch therefore moves no row already shown, and AC7 (`"the history rows did not move or resize (the new fire joined the top group)"`) still holds.
- **The reason line stays, and it wraps in its cell instead of being cut.** `playbook_not_enabled` stays mono beneath the chip (`History.tsx`: `<span className="schedules-mono schedules-clip schedules-reason" data-testid={IDS.fireReason}>`). It is 20 characters at `--type-mono-size: 12px`, about 144px. `.schedules-clip`'s `white-space: nowrap;` wins over `.schedules-mono`'s `overflow-wrap: anywhere;` (same specificity, declared later), so today the line can't wrap. With a ~252px table at the minimum width, keeping it on one line would leave under ~92px for When and Trigger together. Add a scoped override `.schedules-fire .schedules-reason { white-space: normal; overflow-wrap: anywhere; }`, so the code wraps in its cell and is never ellipsized. `.schedules-clip` itself is **not** edited (shared, see the invariants). If the chosen widths leave the code on one line at 900px anyway, the override is dropped (see the condition on its Pin mutations row).
- **Where the fixed row is on screen.** At base, the fixture's `playbook_not_enabled` misses are on the poll's page two (`app/e2e/fixtures/schedules.ts` `POLL_REASONS`, the `// page two` row). In the all-triggers history they load only after two Load older clicks ("All · 23+" then "All · 36+", the AC5 (item 16) pattern in `schedules.spec.ts`). The first page's chips ("fired", "rate limited", "missed · paused", …) already fit the 160px cell. So every new check and the evidence screenshot first page to "All · 36+", assert `skipped.count() >= 1`, and scroll the first such row into view (`scrollIntoViewIfNeeded`). The fixture is not changed.
- **Which screenshot shows the fix.** `STATES` stays at 7 and the PNG count at 14. The `not-fired` screenshot moves from the item-16 AC3 test (`await screenshots(page, "not-fired", testInfo);`, taken before any Load older) into the new AC1 test. That test opens the screen, pages to "All · 36+", presses "Not fired", scrolls the first `playbook_not_enabled` row into view, and calls `screenshots(page, "not-fired", testInfo)`. The not-fired view then shows the wrapped "playbook off: fires are skipped" chips. It is still the mockup's "Not fired" filter of `schedules-populated`. The item-16 AC3 test keeps all its assertions and loses only that one call. `populated` stays the first-load view, matching the mockup.
