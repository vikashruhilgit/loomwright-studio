# Integrations screen evidence (phase 6 item 11)

These are screenshots of the built app's Integrations screen in every designed state, in light and dark mode. Each one was taken by `app/e2e/integrations.spec.ts` against the fixture kernel, with the canned data in `app/e2e/fixtures/integrations.ts`. The account, repos and token are fixture values (`studio-fixture`, `studio-fixture/site`, a `github_pat_E2E…` string), so none of it is real data. The roster is Team's fixture roster: Mason holds the GitHub grant, Wright and Ada do not.

To regenerate the screenshots (macOS):

```sh
cd app && npm run build && INTEGRATIONS_EVIDENCE=1 npx playwright test e2e/integrations.spec.ts --workers=1
```

Without `INTEGRATIONS_EVIDENCE=1` the spec writes its screenshots to Playwright's per-test output directory, so CI never changes these files, and its last test fails if any file in this directory is newer than the run's start. The spec checks behaviour and never compares pixels, because fonts differ between macOS and the Ubuntu CI run. All 18 files were captured on macOS on 2026-10-28. The expiry dates in the screenshots are relative to the capture date (88 days ahead for connected, 8 ahead for expiring, 3 behind for expired).

### How each state is produced

- **Not connected, Connect sheet, connecting, rejected-write, rejected-invalid:** the fixture starts with no connector. The spec opens the sheet, pastes a token and presses Connect. For `connecting` the fixture holds the token route open (`holdToken`) until the screenshot is taken. For the two refusals the fixture answers `422` (`refuse("token_write_scoped")`, `refuse("token_invalid")`) and, as the kernel does for a first connect, leaves a `rejected` row and appends `connector_status`.
- **Connected:** the kernel changes the connector (`change("connected")`: the row changes and `connector_status` is appended), so the screen learns from the feed, as it does for a change made outside this window.
- **Expiring, expired:** the fixture starts with an `expiring` or `expired` row.
- **Unreachable:** the fixture starts connected; `dropNextRead()` closes the kernel when the next `GET /connectors` arrives, and a `connector_status` event makes the screen ask.
- **Dark mode:** the spec sets `data-theme` on the root element and checks that `--ground` differs between the two themes, so a dark capture that silently stayed light fails the run.

## What the spec proves (`app/e2e/integrations.spec.ts`)

| Test | Criteria |
|---|---|
| The pasted token reaches the kernel through the main process | AC9. The fixture's `POST /connectors/github/token` records `{token: <pasted value>}`, the field is `""` and disabled while the kernel is still checking, Connect has `aria-busy`, and the token is absent from the page's markup and text, the URL, every field, both storages, every console line and every line the main process wrote. The scan is non-vacuous: before Connect it finds the token in the field. |
| A write-scoped token, then an invalid one, then a good one | AC9. The sheet stays open with an empty field and a `role="alert"` naming "Pull requests: write → set to Read-only"; the invalid token gets its own copy; the good one connects. The token stays out of the page and console throughout. |
| Empty, connected, Disconnect | AC10. The empty state, then (from the feed) the connected detail with account, permissions, expiry, repos and the one granted agent, then Disconnect: the confirm opens and sends nothing, Cancel sends nothing, confirming sends one `POST /connectors/github/disconnect` and the screen reads "not connected". |
| A `connector_status` update | AC10. A `connector_status` event with a changed answer (connected to expiring) refetches `GET /connectors`, and the screen updates with the window not reloaded (a marker survives), the loading state never rendered (a MutationObserver), and the list pane's and detail header's bounding boxes identical before and after. |
| Expiring, expired | AC12 states, AC13. The band, badge and primary Replace token; the expired replace sheet carries the expired copy. |
| Unreachable | AC12 state, AC7. Status 0 keeps the last answer, disables the writes, and is never the empty state. |
| Keyboard only | AC11. Tab, Enter, Escape and typing only (a pointer-event counter must read 0): Connect GitHub opens the sheet, Escape and Cancel close it with nothing sent, a refused token leaves the field empty and focused, a good one connects, Replace token posts the new token with the field empty afterwards, Refresh reads `?refresh=1` and shows the extra repo, and Disconnect asks first (Escape sends nothing) and then sends one disconnect. |
| Test ids | The spec's copy of the screen's test ids (it cannot import `INTEGRATIONS_TEST_IDS`: see Limits) must all be values of the table in `model.ts`. |
| Evidence gating | AC12. Without `INTEGRATIONS_EVIDENCE`, no file in this directory is newer than the run's start. |

Pin mutations applied to the built app, each of which made the spec fail and was then reverted: `connectGithub` sending `body: {}` (AC9 failed at the recorded body), and the connectors hook clearing its answer at the start of every refetch (AC10 failed at "the screen never flashed its loading state"). With the screenshot helper changed to always write to this directory, the evidence-gating test failed ("no file … is newer than this run's start").

## Limits and deviations

- **AC11: what is and is not met (open: owner decision).** AC11 asks for the walk "via ⌘5 ... using only keyboard.press/⌘K, never a click". Met: the walk is keyboard-only and never clicks (a pointer-event counter must read 0), covering connect, cancel, refuse, replace, refresh and disconnect with Tab, Enter, Escape and typing. Not met: opening the screen with ⌘5 and driving the three commands through ⌘K in the built app. Why: the shell mounts neither `CommandPaletteHost` (only the palette gallery does) nor the screen shortcuts, and mounting them is a shell change outside this PR. Where the commands are pinned instead: jsdom, in `integrations.test.tsx` (ids, enabled flags, same handlers as the buttons) and `connect-sheet.test.tsx` (the commands refuse while a token check is pending). Resolution is the owner's: amend AC11, or a later shell item mounts the palette and adds the ⌘5/⌘K walk.
- **The ⌘K palette and ⌘5 are not reachable in the built app.** The shell does not mount the command palette or bind the screen shortcuts (probed on 2026-10-28: ⌘K, ⌃K, ⌘5 and ⌃5 do nothing). So the keyboard-only test opens the screen by its hash, as Team's spec does, and uses Tab, Enter and Escape. Integrations' three ⌘K commands are pinned in `app/src/screens/integrations/integrations.test.tsx` (jsdom), not driven in Electron here. The brief's pin mutation "delete the Disconnect GitHub command" is therefore caught by that unit test and not by this spec.
- **The spec copies the test ids instead of importing `INTEGRATIONS_TEST_IDS`.** `model.ts` imports Team's model, which reaches the Sessions screen's `.tsx`, and the e2e project's `tsconfig.node.json` has no `jsx` setting, so `npm run typecheck` fails (TS6142) on the import. The spec reads `model.ts` and fails if an id it uses is not defined there.
- **The unreachable capture shows two bands.** The shell's own "Reconnecting to the kernel… Last updated …" band sits above the screen's "Couldn't reach the kernel…" band, because the fixture closes the kernel and the feed drops with it. The mockup's `unreachable` view shows one shared band. This is the screen and shell as built, left as observed.
- **Wording differs from the mockup where the kernel reports different words.** The mockup's refusal reads "Pull requests: Read and write → set to Read-only"; the screen shows GitHub's level as reported ("write"). The token page is shown as selectable text, not a link, because the main process denies every window open (a phase 7 follow-up, as the job brief records). The expired band cannot name a parked playbook and the repo list has no private/public badge, because the contract carries neither.
- **"Refresh reachable repos", not the mockup's "Show reachable repos" (open: owner decision).** The ⌘K command uses the requirement's name and runs the Refresh button's handler (it is enabled whenever the button is: a token in use, expired included, and the kernel reachable), rather than the mockup's "Show", which moves focus to the repos section. `docs/DESIGN.md`'s open point on the name still needs the owner's pick.
- **`token_permissions_unknown` has the screen's own refusal copy, outside the approved design.** The mockup has no copy for it, and the kernel's message names an internal doc, so the sheet says GitHub did not report the token's permissions, Studio refuses it and nothing changed (pinned in `model.test.ts` and `connect-sheet.test.tsx`; the e2e fixture does not refuse with this code).
- **The fixture's routes are the shared interface, not the kernel's.** The real routes are covered by the kernel's own tests; a real token cannot connect until the permissions probe in `docs/OPEN_QUESTIONS.md` resolves.
- All screenshots come from one machine (macOS). The Ubuntu CI run executes the same assertions but does not write these files.
