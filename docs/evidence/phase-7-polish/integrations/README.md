# Integrations polish evidence: the token-to-App switch (phase 7 item 09)

These are screenshots of the built app's Integrations screen for the switch from a token to the GitHub App, in the six views the GUI v2 mockup (`docs/design/mockups/gui-v2.html`) draws for it, each in light and dark mode (12 files). Each was taken by `app/e2e/integrations-switch.spec.ts` against the fixture kernel (`app/e2e/fixtures/integrations.ts`), so no real account, repo, token or browser was involved: `shell.openExternal` is replaced in the main process before any click, and the account, repos and App are fixture values (`studio-fixture`, `studio-fixture-reader`). Dates are relative to the moment of capture. The window is Studio's default 1180 by 760 px.

To regenerate the screenshots (macOS):

```sh
cd app && npm run build && INTEGRATIONS_EVIDENCE=1 npx playwright test e2e/integrations-switch.spec.ts --workers=1
```

Without `INTEGRATIONS_EVIDENCE=1` the spec writes its screenshots to Playwright's per-test output directory, so CI never changes these files, and one of its tests fails if any file in this directory is newer than the run's start. Another test fails if this README stops naming a light and a dark file for a view, or if a file here is not named. The spec checks behaviour and never compares pixels, because fonts differ between macOS and the Ubuntu CI run. The phase 6 evidence (`docs/evidence/phase-6-polish/integrations/`) is not regenerated by this item. All 12 files were captured on macOS on 2026-10-31.

## Polish fixes this PR makes

1. **The token detail's header buttons no longer clip.** With a third button the header overflowed the 1180 px window: Disconnect was cut off at the pane's edge and the "read-only · declared" badge broke across two lines (seen in the first capture of `integrations-token`). The three buttons are now one right-aligned group that drops to its own line when the pane is too narrow, the badge never breaks, and the header no longer shrinks under the rows below it (`integrations.css`, `.integrations-dactions`, `.integrations-dhead`). No new colour or token.
2. **The switch's step 2 is reachable with the real kernel.** `storeApp` over an existing row appended no event, so the setup dialog stayed on step 1 over a token (and after a Disconnect). The kernel now appends one `connector_status` event there (subtask 1 of this item; `docs/architecture/integrations.md` "The port"), and `docs/architecture/app.md` "The step-2 signal" says so. The e2e fixture's `appStored()` mirrors exactly that (token row kept, slug added, one event, no `refused`), and the spec does not fake step 2 with `app-created`; it asserts the dialog stays on step 1 without the event.
3. **Over a token the words never say "not connected".** The list row keeps the token's words with `token · setting up the App` while the setup runs and `token` after a cancel or a failure (`switchRowMeta`). The cancelled view says "Setup cancelled. GitHub is still connected through your token." and every refusal, `setup_expired` and `token_write_scoped` included, shows the one `swf` view (with the write permissions listed for `token_write_scoped`). The no-token path's four outcome views and `appRowMeta` are unchanged.
4. **No "Paste a token instead" over a token.** A token is in use, so the over-token views offer Close and Set up again only.
5. **The row stops saying "setting up" the moment the App connects.** The dialog closes in an effect after the connector reads as an App; the list row now drops the setup words in the same render instead of showing them for one more frame.
6. **Switch is on the palette** as "Switch GitHub to the GitHub App" (`integrations.switch-to-app`), enabled only while a token is in use, the kernel is reachable and no App is connected.
7. **Focus returns to the Switch button** when the dialog closes (Close, or the dialog's own Escape), and to the connector row when the button is gone (the install landed).

## Departures from the mockup

- **No "Proposal" badges and no "Proposal for review" box.** They are review furniture: the owner approved the switch by merging the mockup, so the app shows neither.
- **The App's detail has no Token row.** The mockup's `integrations-app-connected` has "Token: None. The token item is gone." `AppDetail.tsx` has no Token row for any App connection and was not part of this item's files; the token's Keychain row is gone after the switch, and the spec asserts it. Adding the row is a small follow-up.
- **The dialogs keep the shared `role="dialog"`.** The mockup draws the failed view as an `alertdialog`; the screen's setup dialog is one component with one role, and the failure text inside it is `role="alert"`.
- **The list row after a cancel or a failure reads `connected · <account> · token`** while the dialog's outcome view is open, and the ordinary `connected · <account>` once it is closed (the mockup's idle token row always adds `· token`; changing the ordinary row would change the phase 6 screenshots and tests).
- **The setup window's closing time** is shown as the existing dialog shows it (`This setup window closes at <time>.`), on its own line.

## Limits

- **The ⌘K palette is not reachable in the built app.** The shell does not mount the command palette (as for phases 5 to 7), so "Switch GitHub to the GitHub App" is pinned in jsdom, not driven in Electron.
- **The fixture is not the kernel.** `appStored()` and `change("app-connected")` mirror `storeApp` and `recordInstallation`; the real port is covered by `kernel/test/integrations-github-app-port.test.ts`. Nothing here exercised real GitHub or a real browser.
- **A non-refusal `connector_status` from something else during step 1** (the expiry work moving a token from `connected` to `expiring`) would read as the step-2 signal. This is the documented signal; no new shape was added.
- All screenshots come from one machine (macOS). The Ubuntu CI run executes the same assertions but does not write these files.
