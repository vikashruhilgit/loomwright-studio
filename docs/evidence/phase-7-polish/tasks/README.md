# Evidence: the Tasks screen (phase 7, item 03)

This is the polish-gate evidence for the Tasks screen: today's work as four columns ("Waiting on you", "Working", "Parked", "Done today") and an "Other" group that appears only when a card is in it, each card opening to its history and its session's log. The count line ("8 cards · 3 working") sits in the shell's title bar beside the title. Every screenshot comes from the built app running against the fixture kernel, in light and dark mode. All sixteen were regenerated on 2026-11-02 (macOS) for the kind icons on the cards, the shell's crumb in a card's detail and the last-known board. They are evidence for the owner's review, not visual-regression baselines: the spec never compares pixels.

## How they were produced

```sh
cd app
npm run build
TASKS_EVIDENCE=1 npx playwright test e2e/tasks.spec.ts --workers=1 -g AC11
```

The spec writes screenshots here only when **`TASKS_EVIDENCE=1`** is set. Before writing, it deletes every `*.png` in this folder, so the folder always matches the current states. Without the flag, the screenshots go to Playwright's per-test output directory, so a plain `npm run e2e` (locally or in CI) never changes the tree. Each one is a full-window screenshot (1180×760 at 2x, macOS, Electron 44) taken with `data-theme="light"` and then `data-theme="dark"` set on `<html>`. Before taking either, the spec checks that `color-scheme` reads that theme and that the ground colour differs between the two. The last test checks that this README lists exactly the sixteen files below and that the folder holds nothing else.

Times on the cards are real (the fixture's cards were stamped a few minutes before the run, never before today's midnight), so they differ from run to run.

## Differences from the mockup, on purpose

- **Stop and Kill appear on an open card with a live session.** The mockup's history view shows none and says "Tasks has no command of its own". The requirement says Stop and Kill reuse phase 5's session routes, so they sit in the log bar (`StreamingLog`'s own buttons) and `tasks.stop` / `tasks.kill` are in the palette, registered only while such a card is open. Kill asks first. This is for the owner's approval of the PR (D9).
- **A session card has no title in the kernel**, so it is named by its agent and what it ran from ("ada · ad hoc session", "mason · playbook #4"). The mockup's invented titles ("Ada · Weekly changelog draft") and its `why` lines are not in the contract. The app adds one line only: `failed:auth` says "Paused: the subscription token was refused.", as the brief's mapping states.
- **The "Done today" dot is neutral, not green.** That column holds failed and stopped cards too, and green means only what the kernel recorded as done. The badges follow the mockup's tones.
- **The empty state's count line is "0 tasks"** whenever the board is empty, including while the kernel is away. The shell's band still says so.
- **The count line is the title bar's**, through `ScreenDefinition.Subtitle` (`data-testid="titlebar-subtitle"`, with the line in `tasks-subtitle`), as in the mockup; the screen no longer draws its own bar for it.
- **The Other group wraps under the four columns.** The mockup's board is a four-column grid, so a fifth group starts the second row.
- **A history entry for an event kind with no sentence reads "<kind> recorded"** and shows no payload (the mockup's history entries carry invented prose). `task_created` and `task_updated` read as sentences from the fields the kernel's tools write.
- **Cards are real buttons with `aria-disabled`** (not the native `disabled`) while the kernel is away, so focus is never lost to the page.

## Findings for the owner

1. **The kernel closes no set of task states** (the mockup's open point). The board maps `waiting`, `working`, `parked` and `done`, and puts every other word in the Other group, neutral, verbatim. Wright's task tools now name those four words. If the kernel closes the set, `model.ts` is the one place to change.
2. **An unknown run or session status also goes to Other**, neutral, never to Working. The brief fixes this only for a task's free text; the same rule keeps a status a newer kernel adds visible rather than hidden.
3. **The shell mounts no palette and no ⌘ keys**, so a launched window cannot be driven by ⌘6 or ⌘K; that is covered in unit tests only.
4. **`GET /tasks` is read once, at its largest page (200).** If the board holds all 200 and the kernel has more, the screen says "Showing the newest 200 cards; older ones are not shown." and does not page. With fewer cards on the board than the cap it says nothing, even if older non-terminal rows exist beyond the page.
