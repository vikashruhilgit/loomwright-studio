# Evidence: a ticket's pull request on the Tasks board (phase 8, item 14)

This is the polish-gate evidence for the ticket → PR card on the Tasks screen: each ticket's PR as a card on the board (ticket, PR number and state, approvals, CI, owner, and "Waiting on you" with a link to the pending merge approval), and its history (one sentence per PR state change, a link to each session's log, the history's sessions and approvals). Every screenshot comes from the built app running against the fixture kernel, in light and dark mode. They are evidence for the owner's review, not visual-regression baselines: the spec never compares pixels. The phase 7 evidence for the same screen ([`docs/evidence/phase-7-polish/tasks/`](../../phase-7-polish/tasks/README.md)) is untouched.

- Card, words, tones, column and the approval match: [`TicketPrCard.tsx`](../../../../app/src/screens/tasks/TicketPrCard.tsx) and [`ticket-pr.css`](../../../../app/src/screens/tasks/ticket-pr.css), mounted by [`TasksViews.tsx`](../../../../app/src/screens/tasks/TasksViews.tsx) and placed by [`TasksScreen.tsx`](../../../../app/src/screens/tasks/TasksScreen.tsx) (through `buildBoard`'s `columnFor` in [`model.ts`](../../../../app/src/screens/tasks/model.ts))
- The open card: [`TaskDetail.tsx`](../../../../app/src/screens/tasks/TaskDetail.tsx) (facts, the waiting band, session links, the Sessions and Approvals lists), [`useOpenCard.ts`](../../../../app/src/screens/tasks/useOpenCard.ts) (`pickSession`), and the `pr_state_changed` sentence in [`history.ts`](../../../../app/src/screens/tasks/history.ts)
- Unit tests: [`TicketPrCard.test.tsx`](../../../../app/src/screens/tasks/TicketPrCard.test.tsx), [`history.test.ts`](../../../../app/src/screens/tasks/history.test.ts)
- e2e: [`tasks.spec.ts`](../../../../app/e2e/tasks.spec.ts) (the tests named "phase 8 …") over the fixture [`fixtures/tasks.ts`](../../../../app/e2e/fixtures/tasks.ts) (`ticketInit`, `ticketItems`, `ticketHistory`, `waitingMergeApproval`)
- Mockup: [`docs/design/mockups/phase-8.html`](../../../design/mockups/phase-8.html), the Tasks views `tasks-populated`, `tasks-waiting`, `tasks-history` and `tasks-unreachable`

## How they were produced

```sh
cd app
npm ci
node node_modules/electron/install.js   # once, if the Electron binary is missing
npm run build
PHASE8_POLISH_EVIDENCE=1 npx playwright test e2e/tasks.spec.ts --workers=1 -g "phase 8 AC9: every ticket"
```

The spec writes screenshots here only when **`PHASE8_POLISH_EVIDENCE=1`** is set (the switch is shared with the other phase 8 polish folders; the phase 7 `TASKS_EVIDENCE` switch is a different one and is not used here). Before writing, it deletes every `*.png` in this folder, so the folder always matches the current states. Without the switch, the screenshots go to Playwright's per-test output directory, and a test asserts that no file in this folder changed during the run. Each shot is a full-window screenshot (1180 px wide, 2x, macOS, Electron 44) taken with `data-theme="light"` and then `data-theme="dark"` set on `<html>`, after checking that `color-scheme` reads that theme and that the ground colour differs between the two. The window is made taller than the default for these shots so every card (or the whole history) fits in one frame. The last test checks that this README and the folder list exactly the ten files below.

Times on the cards are real (the fixture's cards were stamped a few minutes before the run, never before today's midnight), so they differ from run to run.

## Deviations from the mockup

1. **No triage tally.** The mockup's card and history show "1 fix · 1 reply · 0 answer" and `comment_routed` events with their routes. The kernel serves neither: `TaskTicketPr` (`GET /tasks`) has no tally field and no kernel code records a comment-route event (`grep -rn "comment_routed\|tally" kernel/src app/src` finds nothing outside the diff view). A number here would be a guess, so the card draws no tally. The owner deferred the tally (Launch Pad `LP-CLARIFY`, 2026-11-09) to a kernel follow-up item, which has to add a `comment_tally` field (fix, reply and answer counts the kernel recorded from its comment routes) to `ticket_pr` and a `comment_routed` event. Until then a `comment_routed` event reads through the history's generic "`<kind>` recorded" line (the history shot shows one), and its payload is never shown.
2. **The accessible name keeps the board's `Task <id>:` prefix.** The mockup's `prCard` label starts with the source (`GitHub Issue #14, PR 21: …`). The app keeps `Task <id>: <title>, <state>` (the board's `cardLabel`, which the existing role check `/^(Task|Playbook run|Session) \d+: .+, .+$/` pins) and appends the ticket, PR, approvals, CI, owner, "Waiting on you." and, while the kernel is away, "Last known." words.
3. **Two state tones differ from the mockup.** The mockup draws `open` in the accent tone and `ready` in the ok tone. The brief makes green mean only what the kernel recorded as done, so the badge is ok only for `merged`: `open`, `draft` and `closed` are neutral, `ready` is accent, `parked` is the parked tone.
4. **"Open on GitHub" is not built.** The mockup's open card has a button that opens the PR in the browser. The PR's URL is untrusted kernel text and this item adds no outward navigation, so the PR is shown as `#21 · owner/repo` text.
5. **Head commit, not READY.** The open card shows the head commit (first 7 characters of `ticket_pr.head_sha`) but not the mockup's "Loomwright READY at 11:40" or its explanatory lines ("Loomwright says READY. Your approval lets its gate go ahead."): the kernel serves neither, and the lines would be Studio's own prose presented as a recorded fact.
6. **The history's approvals word is a count.** The tracker's `pr_state_changed` payload carries `approvals` as the number of approvals (`0`), not the repo policy's `n/N` word, so the sentence reads "approvals 0". The card's badge, which comes from `ticket_pr.approvals`, reads the policy's word ("0/2 approvals", "Approve in Studio"). A `from` of `null` reads "opened".
7. **Session links, the Sessions list and the Approvals links are for ticket cards only.** A plain task's history is unchanged. "Show log" and the per-event buttons switch which session's log the pane shows; Stop and Kill follow the session shown, and the Kill confirm names it.
8. **The mockup's footer button for Integrations reads "Open repo policy"** and goes to `#/integrations` (the screen where the owner sets the policy); it writes nothing.
